# 新研究流程：AI、记忆与方向控制

## 当前研究闭环

研究管理入口为 `scripts/research_control.py`，配置位于 `config/research_control.toml`。旧版 v2 多 Agent 自动循环默认停止；原有策略、回测器及记录保留，供建立新基线时核对。

1. `status` 只查看本机 ChatGPT 登录、实验账本与方向状态，不调用模型。
2. `baseline` 在指定的 15 分钟、1 分钟和资金费率数据上运行当前旧策略，按固定训练和验证窗口生成真实基线。缺少成本数据或资金费率覆盖不足时停止。
3. `search` 在指定方向运行一批参数组合；`auto` 自动轮换尚未暂停、参数空间尚未用尽的方向，最多执行配置允许的批次数。搜索完全在本机执行，不消耗模型用量。单批所有候选只在训练窗口排序，只有训练第一名进入固定季度验证窗口。每批训练排行和验证结果写入 `research/batches/`，获选参数追加到实验账本。
4. `record <结果 JSON>` 可手工追加一次真实回测结果。账本要求数据版本、代码版本、评分口径、成本假设、参数和训练/验证结果；策略或回测代码变化时必须重建基线；拒绝包含冻结测试集字段的记录。
5. `propose` 仅生成精简研究摘要，不调用模型。
6. `propose --use-ai` 才会请求 Codex 提出一个可证伪假设。每次使用独立临时目录和会话、只读权限和结构化输出，只提供摘要，不把仓库作为工作目录；建议写入 `research/proposals.jsonl`，不会自动改策略或运行交易。

候选只有在验证分数超过当前基准的最低门槛、足够多验证分块为正、且最大回撤没有明显变差时，才算实质进展。方向连续无实质进展会暂停。下一轮优先探索尚未充分尝试的方向；参数空间用尽后停止，新的搜索范围或策略结构应先作为待验证假设重新设定。门槛和初始参数范围都只是研究配置，需要在最新数据上校准；不能把它们解释成统计显著性证明。

当前仍复用旧策略与旧回测评分，筛选窗口是一次固定训练期加四段顺序验证期，不是完整的滚动重训练。直到取得最新数据并审查基线之前，不应把这个评分或默认参数范围当成实盘上线标准。冻结测试集仅用于研究方案固定后的最后验收，不参与搜索、轮换或 AI 上下文。

## Plus 账户与成本边界

研究 AI 只经本机 `codex exec` 调用。调用前检查 `codex login status` 必须显示 ChatGPT 登录；子进程移除 API Key 环境变量，并忽略用户配置中的其他模型提供商。默认模型为 `gpt-6.1-sol`，模型不可用时直接报错，不自动切换到付费 API。账户由用户在本机登录；项目不保存登录凭证。

只有显式传入 `--use-ai` 才调用模型。默认每个实验周期最多一次、每天最多两次；失败也计入上限，不自动重试。Plus 有共享的五小时和每周用量限制，单次任务实际消耗不固定，因此这个本地次数上限只能减少意外消耗，不能精确保证剩余额度或判断是否会动用账户中另行购买的积分。若将来购买额外积分，应在账户设置中另行管理；本项目不会购买积分。

## 上下文和 checker

AI 每次只收到固定目标、当前同一数据/评分/成本口径下的基准、各方向尝试次数与暂停状态、最近有限数量的实验。完整历史保留在账本中，不让模型自己维护。程序会独立核验 AI 输出字段和所选方向：暂停的方向、已尝试过多的方向或没有否定条件的建议都不会进入下一步。

这里的 checker 首先是确定性的规则，不额外消耗一次模型调用。AI 的文字说明只能作为待验证假设；任何策略晋升都由回测数据和事先设定的标准决定。

这一设计参考了 [OpenAI 的 ChatGPT 登录说明](https://developers.openai.com/codex/auth)、[Codex 非交互调用指南](https://learn.chatgpt.com/docs/non-interactive-mode)、[Plus 用量说明](https://learn.chatgpt.com/docs/pricing)、[scikit-learn 的参数网格搜索](https://scikit-learn.org/stable/modules/grid_search.html)和[时间顺序验证原则](https://scikit-learn.org/stable/modules/cross_validation.html#time-series-split)。这些资料支持账户边界、只读独立调用、可复现穷举和训练/验证隔离；具体交易门槛仍需本项目的数据检验。

## 下一阶段：数据与效果验证

当前仓库没有本地行情文件，尚不能实际复现基线或启动参数搜索。确认框架后，再下载并校验最新 OKX 数据，固定数据版本，运行 `baseline` 复现旧策略，然后启动有限批量搜索。真实结果出来后还需复核评分口径、交易频率、流动性和参数稳定性；实盘接口仍在研究完成之后处理。
